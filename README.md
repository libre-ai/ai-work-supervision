# Libre AI Work Supervision

## Intended use

Give a person and their agents a shared place to describe requested work, inspect progress and blockers, and distinguish decisions from evidence of completion. A request or an accepted brief is not permission for every action an agent could perform.

## Existing candidates and limits

Earlier sources contain work-tracking, specification and authentication components; separate demonstrations use simulated work. These are candidates, not proof of durable authentication, real agent execution or an operational approval chain. This documentary candidate admits no runnable mission application or external action.

## Proposed contracts and authority boundaries

A brief separates stable content from signed acceptance records. Consumers must check the required acceptances as well as content identity. Build Brief permissions are explicit for the resource: ordinary Missions roles do not grant them automatically. Business authorization and acceptance-key admission remain separate responsibilities; the author of a request cannot grant themselves authority. Canonical exchange formats require admission by Contracts.

## Activation criteria

Qualify a complete bounded mission journey with durable state, actual organization membership and explicitly authorized actions. Test revoked or expired authority, refusals, retries and recovery without duplicating external effects. Verify the actual session, specification and authentication authorities independently. Reconcile the exact code and evidence of any proposed demonstration separately; a simulation must remain labeled as such.

The complete journey described above is a criterion for activating the product. A candidate module may be qualified and admitted separately for its own explicit scope, with its own consumer and evidence. Neither that module admission nor the documentary existence of this repository requires a complete Missions journey or completion of other future products.
